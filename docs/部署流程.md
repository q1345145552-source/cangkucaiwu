## 部署流程（严格按顺序，出错即停，不要每步等确认）

### 1. 本地 git 确认干净并推送
```bash
cd /path/to/本地仓库
git status                 # 必须干净，有未提交改动就停下
git fetch origin
git push origin main       # 确认远程 main 是目标提交
```

### 2. SSH 到服务器，确认数据库完好
```bash
ssh root@187.127.124.231

# 连通性 + 完整性快检（PostgreSQL 版：能连上、能查、行数不为 0）
docker exec warehouse-finance-db-1 psql -U postgres -d warehouse_finance -c "SELECT 1;"

# 记下行数基线（部署后要对比，只允许不变或增长）
docker exec warehouse-finance-db-1 psql -U postgres -d warehouse_finance -c \
  "SELECT 'users' t, count(*) FROM users
   UNION ALL SELECT 'leave_requests', count(*) FROM leave_requests
   UNION ALL SELECT 'payroll_records', count(*) FROM payroll_records ORDER BY t;"
```

### 3. 停止容器（只停不删，数据库不停）
```bash
cd /opt/warehouse-finance
docker compose stop backend frontend nginx
# 绝不 rm / down -v；数据库容器 warehouse-finance-db-1 保持运行
```

### 4. 拉取最新代码
```bash
cd /opt/warehouse-finance
git fetch origin
git reset --hard origin/main
git log --oneline -1      # 确认 HEAD = 目标提交号
```

### 5. 复查 .env 关键配置没被覆盖
```bash
# 只输出「键名 + 是否非空」，绝不打印值
grep -nE '^(POSTGRES_PASSWORD|SECRET_KEY|SEED_ADMIN_PASSWORD)=' .env | sed 's/=.*/=<set>/'
# 三个键都在且都非空 → 通过；缺了或空了 → 停下核对
```

### 6. 清缓存并重新构建启动
```bash
cd /opt/warehouse-finance
docker compose build --no-cache backend frontend   # 后端前端都清缓存重建
docker compose up -d                                # 启动（db 会自动保持，不重建）
sleep 8
docker ps --format '{{.Names}}\t{{.Status}}'         # 4 个容器都要 Up
docker logs warehouse-finance-backend-1 --tail 40   # 看有没有 error / traceback
```

### 7. 验证（全过才算成功）
```bash
# ① 健康检查 / 首页（经 nginx，不是直连 8000）
curl -s -o /dev/null -w '%{http_code}' http://localhost/health   # 200
curl -s -o /dev/null -w '%{http_code}' http://localhost/          # 200

# ② 登录接口用错误凭据返回 401 JSON（不是 500）
curl -s -o /dev/null -w '%{http_code}' -X POST http://localhost/api/v1/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"__nobody__","password":"__wrong__"}'
# 期望 401（或后端返回的非 200 业务码），绝不能是 500

# ③ 数据行数复查：与第 2 步基线一致（或只增不减）
docker exec warehouse-finance-db-1 psql -U postgres -d warehouse_finance -c \
  "SELECT 'users' t, count(*) FROM users
   UNION ALL SELECT 'leave_requests', count(*) FROM leave_requests
   UNION ALL SELECT 'payroll_records', count(*) FROM payroll_records ORDER BY t;"

# ④ 数据库挂载正常（named volume，非匿名）
docker inspect warehouse-finance-db-1 --format '{{range .Mounts}}{{.Name}} -> {{.Destination}}{{println}}{{end}}'

# ⑤ 日志 0 报错：无 error / traceback / 迁移失败
docker logs warehouse-finance-backend-1 2>&1 | grep -iE 'error|traceback|失败|exception' || echo "NO_ERROR"
```

### 8. 手动备份数据库（带时间戳）
```bash
cd /opt/warehouse-finance
mkdir -p backups
docker exec warehouse-finance-db-1 pg_dump -U postgres -d warehouse_finance > backups/backup_$(date +%Y%m%d_%H%M%S).sql
ls -lh backups/   # 确认文件生成、大小正常（约 1MB+）
head -c 100 backups/backup_*.sql   # 确认是 PostgreSQL dump 文件头
```

## 铁律（每次都遵守）

1. **出错就停**，报告卡在哪一步，别硬往下走。
2. **容器只停不删**（`stop` 不用 `rm`，更不用 `down -v`），数据靠挂载卷 `warehouse-finance_pgdata` 保留。
3. **任何密钥/密码/Secret 值绝不打印、绝不写进脚本、绝不进日志**；只能确认「键名存在且非空」。
4. **部署前后数据行数对比**：只允许不变或增长，减少 = 立即停并报告。
5. **备份带时间戳**，且备份文件能通过文件头/大小校验。
6. **`.env` 复查**：确认关键 3 行没被 `git pull` 或构建覆盖，覆盖了停下核对。
7. **数据库永不重建**：本系统无 SQLite，PostgreSQL 数据全在挂载卷，`down -v` 会删库，绝对禁止。

## 当前已知注意事项

1. **SSL 证书**：`xtfinance.site` 由 Let's Encrypt 签发，需关注续期；证书挂在 `/etc/letsencrypt`（nginx 只读挂载）。
2. **SECRET_KEY 告警**：后端启动日志会打印一条「SECRET_KEY 使用了不安全的默认值或过短」的 warning，属于历史遗留提醒，不是本次部署错误，不影响启动；但正式生产建议把 `.env` 第 2 行换成 ≥32 位长随机串（改动会影响已登录用户会话，需统一登出重登）。
3. **seed 幂等**：后端每次启动会跑 `scripts/seed.py`，正常输出「DB already seeded」「补了 0 条」即代表没重复造数据、没做破坏性迁移。
4. **GitHub remote 含认证**：服务器 `git remote -v` 里带 token，勿外泄；换 token 用 `git remote set-url`。
