## 已确认的规则

用户对日期矛盾明确选择：“严格按命中条数；超过 3 天但金额或名称命中仍列入”。因此原验证第二步“五天前不出现”被这项回复替代：五天前金额及名称均命中时仍出现，计 2/3，日期不算命中。

三项分别计算：金额完全相同、自然日期相差不超过 3 天（含正负第 3 天）、付款方与客户名称或编号一致。按命中条数降序，同分按日期距离和申报编号稳定排序；0 条排除。名称只规范全半角、空白和大小写后明确相等，不做模糊猜测。客户档案现有“客户账号”可用字段为客户编号 customer_code；没有付款人银行账号字段，本批不新增或猜测银行账号，不把申报收款账户尾号当付款客户账号。

仅建议同仓、同币种、未匹配且可明确归属的合法申报；已匹配和历史归属冲突不进入候选。建议读取不写客户、不改申报，不影响客户余额。未对账查询和建议均限定当前仓库。

## 改动

1. **客户可空**：模型、请求和后端原本已允许空。本批去掉前端必填，空值发送 null，提示“客户不用选 匹配申报后自动带入”。付款方可独立输入，选客户不再覆盖银行付款方内容；到账其他字段、账户校验和幂等流程保留。
2. **保存返回建议**：复用原登记接口，响应增加 suggestions；原请求查询也返回最新只读建议，兼容断网恢复。
3. **未对账每行下拉**：列出客户、金额、币种、日期、命中几条及原因。选择不写入；点该行“确认匹配”即调用现有人工匹配接口。原左右选择和手工确认弹窗保留。无候选显示“暂无匹配建议 请主管认领”。
4. **匹配和撤销**：匹配复用现有 bind_receipt 和余额投影，只新增原归属的修改日志证据。客户为空开始匹配时归属客户，原余额投影自然增加；撤销恢复匹配前为空，原算法自然减回，不退款、不新增/删除银行到账。撤销入口保留。
5. **独立归属保护**：原来已经明确指定的客户、独立账期回款或历史匹配的归属不会被本次撤销误删；这类撤销响应说明“独立客户归属保留，未退款”。不凭建议重分配历史资金。
6. **并发与失败**：保留原 flow/declaration 行锁和状态验证；补齐撤销重读锁，防并发重复撤销。前端确认按钮忙碌保护；旧账号/仓库建议不得提交。匹配或撤销日志失败时与归属/状态整批回滚。

没有修改数据库结构、金额算法、充值申报提交流程、账户选择规则或原权限。源码保护测试确认模型/请求、客户余额投影、账户余额算法、充值提交和到账幂等登记实现与基线完全一致。

## 用户要求的实际返回

### 第一步：金额 3000、同日、付款方 XT10022，客户为空

HTTP 200。完整原始返回见 `step1-create.json`。关键部分：

```json
{"id":1,"amount":3000.0,"currency":"THB","payer_name":"XT10022","customer_id":null,"match_status":"unmatched","created":true,"suggestions":[{"declaration_id":1,"customer_code":"XT10022","amount":3000.0,"matched_count":3,"matched_conditions":["日期相差不超过3天","金额完全相同","付款方与客户名称或编号一致"]}]}
```

完整列表排序为申报 1、2、4、3，命中数 3、2、2、1。此时客户实收仍为 0，银行到账一笔 3000。五天前申报 4 仍列入，日期条件不命中，见 `step2-five-days.json`。

### 第三步：下拉确认匹配

HTTP 200，实际返回：

```json
{"id":1,"flow_id":1,"declaration_id":1,"customer_id":1,"customer_code":"XT10022","amount":3000.0,"currency":"THB","message":"已匹配到 XT10022 的 3,000.00 THB"}
```

客户实收/预收 0 → 3000，到账 customer_id=1，申报 matched；银行到账仍一笔，账户余额仍 3000。重复确认不产生第二笔。完整查询与余额见 `step3-match.json`。

### 第四步：撤销

HTTP 200，customer_binding_reverted=true；客户实收 3000 → 0，到账客户恢复空、申报恢复 unmatched；银行到账与账户余额均保留。重新匹配后客户实收为 3000，仍仅一次实收。见 `step4-undo.json`。

### 第五步：客户不填

另一笔金额 123、未知付款方的到账 HTTP 200，id=2、customer_id=null、match_status=unmatched、created=true。完整返回见 `step5-empty-customer.json`；有建议也不自动归属。
