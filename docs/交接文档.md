## 5. 数据库

**数据库**：`warehouse_finance`，共 **44 张表**，当前约 11 MB。

**核心业务表**：

| 表 | 说明 |
|----|------|
| `users` | 用户账号（含角色） |
| `warehouses` | 仓库 |
| `user_warehouses` | 用户-仓库多对多关联（多仓权限来源） |
| `employees` | 员工档案（含护照/工作证/照片等 29 个字段） |
| `clock_in_records` | 打卡记录（4 时段） |
| `overtime_tasks` / `overtime_assignments` | 加班任务与分配 |
| `leave_requests` | 请假（病假） |
| `rest_days` | 休息日 |
| `absences` | 缺勤标记 |
| `payroll_records` | 工资单（支持上下半月） |
| `customers` | 客户 |
| `suppliers` / `supplier_products` / `supplier_logistics_prices` | 供应商与产品价格 |
| `payable_bills` / `payable_plans` | 应付账单与账期计划 |
| `purchase_orders` | 采购单（供应商下单） |
| `recharge_declarations` / `incoming_flows` | 充值申报与到账流水 |
| `expense_funds` / `expense_fund_items` / `expense_records` | 备用金 |
| `fund_recharge_requests` | 备用金充值申请 |
| `reimbursements` / `reimbursement_items` | 报销 |
| `credit_customers` / `credit_repayments` / `credit_shipments` | 账期/赊销 |
| `income_records` / `income_expense_categories` | 收支与类别 |
| `reconciliation_results` | 对账结果 |
| `group_orders` / `group_order_participants` / `market_items` | 拼单与商品 |
| `exchange_rates` | 汇率 |
| `audit_logs` | 操作审计日志 |
| `system_settings` | 系统设置 |

**重要**：`employees` 表字段较多（照片、护照、工作证、转正、离职、黑名单等），改字段时必须用 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`，避免丢数据。

## 6. 角色与权限体系

| 角色 | 代码值 | 权限层级 | 说明 |
|------|--------|---------|------|
| 超级管理员 | `super_admin` | 3 | 只管用户和系统设置、仓库管理、操作日志 |
| 仓库管理员 | `warehouse_admin` | 2 | 管理自己名下仓库，可多仓切换、建仓 |
| 财务/员工 | `staff` | 1 | 仓库业务操作，通过 `extra_permissions` 细粒度授权 |
| 仓库劳工 | `warehouse_labor` | 0 | 仅打卡签到、考勤、加班、我的工资单 |

**多仓库机制**（重点）：
- 权限来源是 `user_warehouses` 关联表（不再用 `users.warehouse_id`）。
- 登录接口返回该用户可访问的仓库列表。
- 前端顶部仓库切换器加载可选仓库；选中的仓库 ID 存在内存 + `localStorage`。
- 后端通过请求头 `X-Warehouse-ID` 获取当前仓库，并校验用户是否有权访问。
- 仓库管理员在「报表中心」页面可见「总仓汇总」选项，汇总**仅限自己名下所有仓库**，绝不跨管理员。

## 7. 功能模块

**财务板块**：仪表盘、客户档案、仓库管理、账户、充值申报、到账流水、对账、运营收支、其他收支、备用金、报销、账期、报表、台账。

**供应商板块**：供应商管理、应付账款、账期计划。

**拼单板块**：商品展示、拼单。

**员工管理板块**：员工档案、工作考勤、加班管理、工资管理。

**系统设置**：系统设置、操作日志。

**劳工端**：打卡签到（4 时段按顺序）、工作考勤、加班管理、我的工资单。

**语言**：中文 / 泰语 / 缅甸语三语，管理员端下拉选择，劳工端默认缅甸语，选择记忆在 `localStorage`。

## 8. 账号体系

- 初始账号由 `backend/scripts/seed.py` 生成。
- 超级管理员账号：`admin`。
- 每个仓库自动生成两个账号：`{仓库编码小写}_admin`（仓库管理员）和 `{仓库编码小写}_staff`（财务）。
- **初始密码统一由 `.env` 中的 `SEED_ADMIN_PASSWORD` 决定**；未设置时 seed 会随机生成并打印到容器日志。
- 密码查看/重置：登录服务器后执行 `cat /opt/warehouse-finance/.env` 查看 `SEED_ADMIN_PASSWORD`。

> ⚠️ 当前数据库中存在大量测试账号和测试仓库（如 `banxian`、`123`、`1234`、`test_staff1`、`staff_auto`、`1仓`~`4仓` 等），上线前需要清理。

## 9. 常用运维命令

```bash
cd /opt/warehouse-finance

# 查看容器状态
docker compose ps

# 查看日志
docker compose logs -f backend
docker compose logs -f frontend
docker compose logs -f nginx

# 重新构建并部署（前端代码改动后）
docker compose build frontend --no-cache
docker compose up -d frontend

# 后端 + 前端全量重建
docker compose build backend frontend
docker compose up -d

# 重启所有服务
docker compose up -d

# 进入数据库（本机回环 5434）
docker exec -it warehouse-finance-db-1 psql -U postgres -d warehouse_finance

# 备份数据库
docker exec warehouse-finance-db-1 pg_dump -U postgres warehouse_finance > backup_$(date +%F).sql

# 恢复数据库
cat backup_xxx.sql | docker exec -i warehouse-finance-db-1 psql -U postgres -d warehouse_finance
```

**前端构建注意**：改前端后必须 `docker compose build frontend` 重新构建（`.next` 缓存会在 Dockerfile 中先删除），否则环境变量 `NEXT_PUBLIC_API_URL=/api/v1` 可能不生效。

## 10. 安全注意事项

1. **`.env` 文件勿泄露**：含 `SECRET_KEY`、`POSTGRES_PASSWORD`、`SEED_ADMIN_PASSWORD`，已被 `.gitignore` 忽略，不入库。
2. **GitHub remote 含 Token**：服务器 `git remote -v` 可见认证 Token，勿外泄；如需更换可重新 `git remote set-url`。
3. **数据库不对外**：PostgreSQL 仅绑定 `127.0.0.1:5434`。
4. **生产模式**：`docker-compose.yml` 的 `command` 覆盖了后端 Dockerfile 的 `--reload`，实际以生产模式运行（无自动重载）。
5. **SSL 证书**：`xtfinance.site` 证书有效期至 **2026-10-05**，需提前续期。
6. **SSH 认证**：服务器使用密码认证，建议后续改用 SSH 密钥登录。
7. **`deploy.sh`**：被 `.gitignore` 忽略，未在仓库中，部署靠手工执行上面的 docker compose 命令。
