# 第十八轮：预支审批、驳回及工资过滤

基线8882a6a。本轮只修改两个业务文件：employee_advance.py新增审批动作，payroll.py新增已通过过滤条件（另补枚举import）。没有前端、模型、迁移、备用金或历史数据改动，未部署。

## 接口

- `POST /api/v1/employee-advances/{advance_id}/approve`：无需请求体。
- `POST /api/v1/employee-advances/{advance_id}/reject`：JSON `{"reject_reason":"原因"}`。
- 只有warehouse_admin能用；supervisor、staff、super_admin、warehouse_labor均403“只有仓库管理员可以审批预支”，不依赖他们是否勾了员工预支权限。
- 按当前选中仓库查询预支并加行锁；不存在、外仓均404“预支记录不存在”。未选仓库要求先选仓库。
- 只允许pending→approved或pending→rejected，禁止重复审批和对最终状态再变更。
- 驳回原因必填，空白也算空；超过500字提示中文错误，避免数据库字段溢出。
- 状态和修改日志同一数据库事务，不单独commit；日志失败审批回滚。

## 第三、四步拒绝结果

| 场景 | HTTP | detail |
|---|---:|---|
| 主管调通过/驳回，有无预支权限均一样 | 403 | 只有仓库管理员可以审批预支 |
| 财务、超管、劳工调两个动作 | 403 | 只有仓库管理员可以审批预支 |
| 已通过再通过 | 400 | 该预支已通过 |
| 已驳回再通过 | 400 | 该预支已驳回，不能审批通过 |
| 已通过再驳回 | 400 | 该预支已通过，不能驳回 |
| 已驳回再驳回 | 400 | 该预支已驳回 |
| 驳回未传JSON、空对象、null、空串、纯空白 | 400 | 请填写驳回原因 |
| 外仓或不存在的ID | 404 | 预支记录不存在 |

重复/错误状态请求没有新增审批日志或改写审批时间。

## 第五、六步：工资实发差100

测试员工按日400，10月16/17日每天09:00/12:00/13:00/18:00打卡，共16小时，基础工资800。另外保留一条已驳回预支200元。

| 场景 | 基础工资 | 预支扣款 | 实发 | 已驳回200元 |
|---|---:|---:|---:|---|
| 100元待审批，显式算工资 | 800 | 0 | 800 | 不扣 |
| 老板批准该100元，但尚未重算 | 原工资单所有字段不变 | 仍0 | 仍800 | 不扣 |
| 手动重算 | 800 | 100 | 700 | 不扣 |
| 再重算一次 | 800 | 仍100 | 仍700 | 不重复扣 |

实发差额800−700＝100，正好一百。待审批与驳回预支的deducted_amount均保持0。

另完成真实新建链路：给纳入考勤的主管绑定员工档案→主管POST新建自己100元预支→返回pending→算工资800不扣→主管自批403→管理员通过→手动重算700。

## 结转口径

已通过预支1000，第一期工资800：扣800、实发0、剩余欠款200，预支状态partial。下一期工资400：扣剩余200、实发200、剩余0，预支状态deducted。排序、扣款、回退和结转算法没有修改。

## 第七、八步：老单与留痕

- 审批前后逐列比较工资表，旧工资单不变；只在人工调用重算接口时创建新单并作废旧单。
- 既有测试老单金额、状态逐列保持不变；不会启动时或审批时重算。
- 修改日志模块为菜单英文键 `employee_advances`，动作approve/reject，保存操作者ID/姓名、记录编号、仓库及审批前后状态。
- after_data包含amount=100、reviewer_id=1、reviewed_at、approval_status及中文approval_status_label；驳回另含reject_reason。
- GET `/api/v1/history?module=employee_advances`返回2条对应审批/驳回记录。
- 注入日志写入失败，通过和驳回均回滚，记录保持pending。
- 当前修改日志前端没有employee_advances、approve/reject的中文映射，全部模块仍可查看记录，名称会回退显示英文键；详情状态有“已通过/已驳回”中文值。本轮按要求不改前端。
