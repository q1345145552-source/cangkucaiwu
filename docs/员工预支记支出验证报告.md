# 员工预支记支出验证报告

验证日期：2026-10-19。全部金额和请求来自本地独立测试库，没有连接或修改生产数据库；本轮不部署。

## 实现范围

- 沿用 `IncomeExpenseCategory`、`ExpenseRecord`，分类为运营支出下面的“员工预支”，按仓库和名字查找，不用固定编号。启动时给所有现有仓库补分类；新仓第一次记预支也能创建分类。
- 新预支创建即通过时，同一事务创建一笔支出；主管给自己记的待审批预支，在老板审批通过的同一事务创建。待审批、已驳回不创建支出。
- 支出日期用预支日期，金额、币种、仓库沿用预支，备注含员工姓名及预支单号。预支返回 `expense_record_id`，普通及合并支出列表返回 `employee_advance_id`、`employee_id`，可以互查。
- 原审批角色限制、状态判断和仓库隔离保留。审批记录加行锁，支出关联加唯一索引；重复审批在创建支出之前拒绝。
- 按用户确认的删除规则，删除新预支时，同一事务删除关联支出并写修改日志。关联支出不能从运营收支里单独改删。
- 没有增加撤销接口。工资计算、扣预支、确认、发放、重算的代码没有改，历史工资单不自动变化。

直接通过的创建场景也已测试：仓库管理员新建、主管给别人新建、已授予权限的财务新建，均立即关联一笔支出。原角色规则没有改变。

## 第四步：工资抵扣没有重复记支出

## 第五步：老数据没有补账

- 独立测试库预置3条旧预支：已通过、待审批、已驳回各1条。运行分类补齐两遍，旧预支仍 **3条**，关联支出 **0条**，运营支出总条数从 **0到0**。
- 旧待审批记录在上线后再通过，仍不补支出。
- 真实 PostgreSQL 迁移测试另预置一笔旧支出50元；迁移重复执行后仍 **1笔、50元**，3条旧预支的金额、状态、抵扣金额保持原值，关联编号全部为空。

本轮不是按日期推断新旧。`employee_advances` 新增以下字段，启动迁移每条语句独立保存点：

| 字段 | 作用 | 老记录默认值 |
| --- | --- | --- |
| `expense_tracking_enabled` | 只有本轮上线后通过新建接口生成的预支才记支出 | false |
| `expense_record_id` | 关联运营支出，唯一索引 | null |
| `fund_item_id` | 精确关联原有备用金开销，供去重和删除时使用，唯一索引 | null |

启动迁移只加列、索引及分类，没有插入旧预支对应的支出。分类重复运行不重复建。分别注入五条迁移语句失败后验证保存点回滚，先前迁移仍存在；恢复后可重跑完成。

## 备用金来源和显示

旧预支代码在选择备用金时已经写入一条备用金开销。本轮保留其原金额、币种、可用额度计算和业务接口，新增精确关联：

- 合并成本查询只在新预支通过后显示“员工预支”那一条，排除同笔备用金虚拟明细，避免算两次；新预支未通过或被驳回时不通过合并查询计成本。旧备用金开销不追溯、不改写。
- 公司实际资金查询不会把这条新支出当成公司第二次付款；普通流水也不新增同笔重复支出。
- 删除新预支时，同时清除它精确关联的备用金开销，避免预支删除后这条开销又从合并成本里浮现。旧预支及无关联的备用金开销不按名称、金额猜测处理。
- 人民币备用金预支1,000测试：运营支出仅 **1笔、1,000 CNY**；公司实际资金仍只有原备用金领用5,000一笔，没有第二笔1,000。
- 前端仅两处关联文案：运营列表显示“预支联动明细”；对账展开明细显示预支姓名及单号，避免把支出编号误称为备用金开销编号。排版和其他操作没有改。
