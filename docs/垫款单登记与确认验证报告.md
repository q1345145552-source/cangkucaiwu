# 垫款单登记与确认验证报告

验证日期：2026-10-18（泰国时间）。所有写入、上传、确认、工资发放均在本机独立临时测试库进行，没有连接或修改生产数据库。本轮只做垫款登记和确认，尚未部署。

## 本轮范围

- 新增独立 `cash_advances` 表和 `/cash-advances` 页面；菜单位于运营收支所在的“财务(日常开支)”分组。
- 权限名从唯一清单登记为“垫款单”，英文键 `cash_advances`，可勾选。已有菜单的地址、图标、顺序、角色规则不变，只插入这一项。
- 新建仅仓库管理员、勾选权限的主管可用。财务勾选后只读。确认、驳回仅仓库管理员可用；超管、劳工不能操作本模块。
- 记录账号或手填垫款人姓名；未选账号且未填姓名时使用操作人。账号来自当前仓库，其他仓库和停用账号不能被绑定。
- 金额用 NUMERIC(14,2) 保存，必须大于零，最多两位小数。用途为工资、采购、费用、其他。记录凭证、创建人/时间、确认或驳回的人/时间和驳回原因。
- 待确认、已驳回不计入公司欠款；已确认计入金额减已归还金额。本轮已归还金额为零，没有归还入口和接口。
- 确认、驳回使用行锁并限制只能处理待确认状态，记录修改日志，与状态变化处于同一事务。
- 没有改工资、报销、备用金、支出或资金流水的业务代码；登记和确认不生成成本或支出，不会把主管垫款重复记成本。

## 数据库及补权

启动脚本 `backend/scripts/seed.py` 的 `_migrate_cash_advances` 使用 `CREATE TABLE IF NOT EXISTS` 和 `CREATE INDEX IF NOT EXISTS`，每条在独立保存点内执行。原财务数据不回填、不重算。

新表共18列：`id / warehouse_id / payer_id / payer_name / advance_date / amount / purpose / description / voucher_path / status / repaid_amount / created_by_id / created_by_name / created_at / reviewed_by_id / reviewed_by_name / reviewed_at / reject_reason`。

补权仍集中在 `backend/app/services/permission_migrations.py`，标记：

`cash_advances_supervisor_staff_backfilled_v1_20261018`

只给执行时已存在的主管和财务追加“垫款单”；其他角色不补。重复执行返回0；手动取消后重启不补回。既有标记和权限名称没有更改。

## 接口清单

| 方法 | 地址 | 规则 |
|---|---|---|
| GET | /cash-advances | 本仓列表；日期、状态、垫款账号/姓名筛选、分页 |
| GET | /cash-advances/summary | 本仓全部已确认未归还汇总；人数、总额、每人一行 |
| GET | /cash-advances/payers | 本仓可选账号，不借用账号管理权限 |
| POST | /cash-advances/voucher | 主管或仓库管理员上传照片，权限及仓库校验，最大10MB |
| POST | /cash-advances | 主管或仓库管理员登记，初始待确认 |
| POST | /cash-advances/{id}/confirm | 仅仓库管理员确认 |
| POST | /cash-advances/{id}/reject | 仅仓库管理员驳回，原因必填 |

所有读取和写入都限定当前选中仓库；管理员在“全部仓库”模式下须先选择一个仓库。

## 拒绝和边界

- 财务、劳工、超管新建或上传：403；主管未勾权限：403，无此操作权限。
- 主管、财务、劳工、超管确认或驳回：403，`只有仓库管理员可以确认或驳回垫款单`。
- 驳回缺原因、空串、空白字符：400，`请填写驳回原因`；填“凭证不符”后成功，状态已驳回，不增加欠款。
- 已确认、已驳回、已归还均不能再次确认/驳回。
- 跨仓确认/驳回404；外仓列表0条、汇总0人0元；伪造外仓请求头不扩大权限。
- 0、负数、NaN、Infinity、超过两位小数、无效用途或日期均不创建记录。
- 同一垫款人多张单合并；0.10+0.20精确汇总0.30。4000+3000汇总7000，不重复计算人数。待确认999不计入欠款。
- 模拟修改日志写入失败时，登记和确认整体回滚，没有半成功记录。
