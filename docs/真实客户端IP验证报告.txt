一、启动参数及代理信任范围
选用 --proxy-headers，并由新启动入口设置 FORWARDED_ALLOW_IPS。
docker-compose 为后端配置 TRUSTED_PROXY_HOSTS=nginx。
scripts/start_server.py 启动时通过 Docker DNS 解析 nginx 的精确 IPv4/IPv6 地址，
将解析结果写入 FORWARDED_ALLOW_IPS，再 exec python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --proxy-headers。
不使用 *，不信任整个 172 网段，不硬编码当前容器 IP；Uvicorn 仍使用项目固定的 0.30.6。
启动日志会打印这份可信代理 IP 清单，便于部署后与 nginx 容器地址核对。
旧版本对代理地址采用精确地址匹配，所以先解析主机名，不能直接把 nginx 主机名或 CIDR 当成已生效的白名单。
nginx DNS 暂未就绪时短暂重试；始终解析失败就拒绝启动，不降级为信任所有来源。
后端镜像默认开发模式的 --reload 保留，compose 生产启动仍不启用 reload。
本轮没有改数据库、数据卷、nginx 配置、前端、业务计算和权限规则。
如 nginx 被重新分配地址，需要重启后端以重新解析白名单；部署或重启后应核对该白名单与实际 nginx 地址一致。

二、统一取 IP 及防伪
新增 app/core/client_ip.py 的 get_client_ip，所有操作日志共用这一函数。
正常 nginx 单跳链路的 X-Forwarded-For 最前值经可信代理验证后使用；没有该头时，从可信 nginx 的 X-Real-IP 获取；再没有则使用连接地址。
安全边界：当前 nginx 用 $proxy_add_x_forwarded_for，会保留访客自行提交的前置值，再追加 nginx 实际看到的来源。
所以不能盲取第一个值。Uvicorn 先根据可信 nginx 身份从右向左剥离代理链，
应用仅接受与已校验来源相符的头值；对原始可信代理连接也采用同样的链校验。
直接访问后端的非白名单来源，即使同时伪造 X-Forwarded-For 和 X-Real-IP，也只记录连接来源。
IPv4/IPv6 统一验证、规范化，非法头值不能成为日志 IP。
安全依据及代理头注意事项：https://www.uvicorn.org/deployment/

三、成功登录日志及查询
成功登录标记已校验的账号 ID 和仓库，审计中间件记录 action_type=login、module=auth、真实 IP。
不依赖登录请求伪造的 Authorization 或 X-Warehouse-ID 来决定登录人和仓库。
每次成功登录记录一条；失败登录保持原来的 401，不记成成功登录。
不记录密码、请求正文、Authorization、响应访问令牌；审计失败仍不会影响正常登录。
现有 GET /api/v1/settings/logs 增加 ip_address 返回字段，其余字段和权限过滤保留。
原前端操作日志没有 IP 列，按本轮“不改前端”的要求保留；可通过接口或数据库核对 IP。
旧日志没有更新、删除或回填。
