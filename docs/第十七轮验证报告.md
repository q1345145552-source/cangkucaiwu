# 第十七轮：预支审批状态

本轮仅修改后端。验证使用临时 SQLite 数据库的真实 HTTP 请求及本机嵌入式 PostgreSQL，未访问线上数据库，未部署。

## 四个字段

表：`employee_advances`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| approval_status | VARCHAR(20)，非空，默认 approved | pending 待审批、approved 已通过、rejected 已驳回 |
| reviewer_id | INTEGER，可空，关联 users.id | 审批人；删除审批账号时置空 |
| reviewed_at | TIMESTAMPTZ，可空 | 审批时间 |
| reject_reason | VARCHAR(500)，可空 | 驳回原因 |

原有 `status`（unpaid / partial / deducted）是扣款进度，保持原义，不与审批状态混用。状态枚举和中文名称集中在 `app.models.employee_advance`，下一轮可直接引用。

## 启动迁移

`backend/scripts/seed.py` 中新增 `_migrate_advance_approval_columns`，在建表之后调用。四列均使用 ADD COLUMN IF NOT EXISTS，每列独立保存点，数据回填也独立保存点。

新增列默认 approved，已有记录立即保留旧的生效状态；再用 `WHERE approval_status IS NULL` 回填兼容已经部分加列的环境。没有每次启动全表覆盖状态，因此新产生的 pending / rejected 不会被重启改回 approved。

真实 PostgreSQL 旧表迁移结果：

| 编号 | 金额 | 已扣 | 原扣款进度 | 迁移后审批状态 |
| --- | --- | --- | --- | --- |
| 1 | 100 | 0 | unpaid | approved |
| 2 | 200 | 50 | partial | approved |
| 3 | 300 | 300 | deducted | approved |

迁移前后均为 3 条。原有全部字段逐列一致，新增 reviewer_id、reviewed_at、reject_reason 均为 NULL。

同一事务内连续迁移、提交后再次启动、部分字段已存在均通过。人为令任意一列失败时，其他列和之前的迁移事务仍保留；恢复后重跑成功。已有 pending / rejected、审批人、审批时间、中文驳回原因在重复迁移后完全不变。

## 三种新建情况的真实响应

```json
[
  {"message":"预支记录已创建","id":1,"approval_status":"approved","approval_status_label":"已通过","reviewer_id":null,"reviewed_at":null,"reject_reason":null},
  {"message":"预支记录已创建","id":2,"approval_status":"pending","approval_status_label":"待审批","reviewer_id":null,"reviewed_at":null,"reject_reason":null},
  {"message":"预支记录已创建","id":3,"approval_status":"approved","approval_status_label":"已通过","reviewer_id":null,"reviewed_at":null,"reject_reason":null}
]
```

- 编号 1：管理员给主管记预支 100，直接已通过。
- 编号 2：主管给自己记预支 100，待审批。
- 编号 3：同一主管给劳工记预支 100，直接已通过。

没有新增审批动作，所以自动通过的审批人、审批时间仍留空，不伪造人工审批记录。财务、超管原有创建权限及原默认生效行为保留。

“自己”按员工档案关联、账号关联及已有开关历史确认；关闭考勤后保留的原本人档案仍需审批。同名劳工不被误判为主管本人。客户端伪造 approval_status、reviewer_id 不影响服务端判定。

## 列表与本人查询

- GET /employee-advances 每条新增上述四字段，并额外返回 approval_status_label 中文名称；原字段全部保留。
- 可传 approval_status=pending / approved / rejected，也支持 待审批 / 已通过 / 已驳回。不传返回全部，非法状态返回 422。
- 对测试中三种状态逐一筛选，均只返回对应记录；原 employee_id、period、仓库范围继续叠加。
- 原本人接口 GET /employee-advances/my-debt 保留 total_by_currency，并新增 data，列出原查询范围内本人的未扣清预支及审批字段。实测只返回本人两条，不包含给劳工记的第三条；已驳回样例的审批人、时间、中文原因均正确返回。
- 没有新增审批/驳回路由，没有新增批量写接口。原新建员工/备用金仓库归属和删除归属校验保留，跨仓新建及删除均被拒。
