# 代录请假直接生效

## 检查结论与改动范围

基线提交 `cc9660d` 中，`POST /api/v1/attendance/leaves/admin-record` 已经使用 `status="approved"`，并设置 `reviewed_by=current_user.id`、`reviewed_at=thai_now()`。不存在该路径仍创建 pending 的代码。本轮保留已有正确逻辑，通过接口及数据库验证它实际生效；不修改历史代录记录。

本轮实际修复重复代录：原来同日非驳回记录被静默跳过，HTTP仍200；现在对日期范围预检，存在 approved/pending 即HTTP400，中文提示“该员工这一天已有请假记录”。已驳回记录不阻挡重新代录。整个范围先检查再插入，避免前几天建成、后一天冲突时出现部分成功。成功响应的 message/created/skipped 结构保留，skipped为0。

只有代录函数业务代码变化。员工申请、审批、驳回、工资、工时计算、配置服务、前端、模型、启动脚本均未修改。原有角色权限、员工仓库归属和离职校验保留。

## 第一至第四步实际返回

以下为独立 SQLite 测试库，通过真实 ASGI 路由请求所得，不是生产数据。管理员ID1、主管ID4分别重复所有四种时长场景，均通过。返回摘录保留实际字段值；创建接口本身不返回状态，状态从原有列表接口核实。

### 1. 管理员代录全天假

创建HTTP200：

```json
{"message":"已代录 1 条请假，跳过 0 天","created":1,"skipped":0}
```

列表记录摘录：

```json
{"id":1,"employee_id":1,"leave_date":"2026-10-04","duration_type":"full","status":"approved","hours":null}
```

考勤摘录：

```json
{"status":"leave","status_label":"请假","clock_hours":0.0,"work_hours":0.0}
```

数据库另查 `reviewed_by=1`（主管为4），`reviewed_at` 非空；实际报备时间按输入仍为 `2026-10-03T10:00:00`，没有被代录操作时间覆盖。

### 2. 代录两小时假

创建HTTP200，同上成功响应。列表 `duration_type="hours"`、`hours=2.0`、`status="approved"`。

考勤摘录：

```json
{"status":"hours_leave","status_label":"请假2小时","leave_hours":2.0,"clock_hours":8.0,"work_hours":6.0}
```

四次打卡09:00/12:00/13:00/18:00；人工算工资后同为6小时，测试日薪400元对应基础工资300元。

### 3. 代录下午半天假

创建HTTP200，同上成功响应。列表 `duration_type="afternoon"`、`status="approved"`。

配置中心作息09:00–12:00、13:00–18:00；实际上午两次打卡09:00/12:00。

```json
{"status":"half","status_label":"半天","leave_hours":5.0,"clock_hours":3.0,"work_hours":3.0}
```

下午假折算5小时；实际上午打卡3小时不被重复扣除。人工算工资同为3小时，基础工资150元。额外验证上午假折算3小时、下午实际工时5小时、基础工资250元。

### 4. 重复、驳回、重新代录

同员工同日再次代录HTTP400：

```json
{"detail":"该员工这一天已有请假记录"}
```

管理员驳回原记录HTTP200：

```json
{"message":"已驳回"}
```

再次代录HTTP200：

```json
{"message":"已代录 1 条请假，跳过 0 天","created":1,"skipped":0}
```

新记录重新为approved，原驳回记录保留。原有pending也会被拦；旧库同日多条approved返回400而非scalar_one异常。范围中一天冲突时，整个请求不新增记录，原记录逐列不变。

## 员工申请与历史数据

劳工自己提交两小时假：HTTP200，数据库pending；审批前考勤仍8小时。管理员批准HTTP200后考勤变为6小时。员工申请函数AST与基线完全一致。

代录、列表、考勤查询前后逐列对比工资记录，旧单未自动重算；验证工资只通过显式计算接口创建测试新单。没有运行历史数据更新或迁移。三天范围成功代录创建3条，均approved且保留操作者、时间和2小时值。
