# 预支选主管与自动建档

基线 cbaddcb。本轮完成选人、按需自动建档和未纳入考勤管理人员的工资名单排除；未部署，所有数据均来自本机隔离测试库。

## 接口和绑定方式

新增 `GET /api/v1/employee-advances/recipients`，使用员工预支权限，限定当前仓库。包含在职未删除员工档案，及本仓有效主管、仓库管理员账号；已在档案中出现的账号不会重复追加。姓名、角色标记、工号和编号来自后端，界面不另外维护角色名单。

选项用 `employee:编号` 和 `user:编号` 区分，避免两个表的编号相同导致选错。创建接口仍支持原 `employee_id`；没有档案的管理账号可传 `user_id`，两字段必须只选一个。普通员工继续走原员工编号路径。

按账号绑定编号、考勤关联编号及关闭考勤历史中的编号复用档案，不根据姓名猜测。提交时先对账号加行锁，避免同一账号同时建两条档案；已有唯一账号绑定约束仍保留。新档案与预支处于同一个请求事务，来源/备用金校验失败时一起回滚。

新档案：姓名取显示名，岗位仓库主管，仓库取该账号主仓，状态 regular（正式），关联 user_id，入职时间取泰国当天；两个模板为空。工号沿用系统已有规则，通过关联账号的 username 显示，没有新增或复制另一份工号字段。不修改账号 attendance_enabled / attendance_employee_id / attendance_enabled_at；未开启者继续关闭，已开启者保持原值。

已离职、已删除、跨仓或绑定冲突的档案不会通过新建绕开；停用账号不能作为新增账号对象。已有档案的路径保留既有离职、删除和仓库校验。主管给自己记的仍待审批；管理员记的、主管给他人记的仍按原规则已通过。

## 工资名单验证（另一套独立隔离库）

工资预览、批量计算、指定员工计算及重算共用的准备阶段增加同一个名单过滤：岗位是仓库主管/仓库管理员，身份解析关联的同仓账号角色是主管/仓库管理员，且 attendance_enabled 关闭时跳过。劳工和财务不受该过滤影响。过滤发生在模板校验和工资生成之前，不给这类空模板管理档案报模板错误，也不出零元单。

测试造两个未开考勤的管理档案（员工编号3、4），工资计算后两人均无新工资单。对照名单：

| 员工编号 | 姓名 | 实发 |
|---|---|---:|
| 1 | 员工1 | 400.00 |
| 5 | 开启考勤主管 | 400.00 |
| 6 | 财务 | 400.00 |

三名对照人员使用相同模板、同一天四次打卡。普通员工、开启考勤主管和财务都继续生成工资；没有改变计算公式。只指定未开考勤管理档案计算时不生成记录。此前已有的全部工资记录逐字段快照一致，不自动作废或重算。

以后通过原账号编辑接口打开该主管纳入考勤，复用预支时创建的员工档案，不重复建档，薪资模板仍须老板配置。关闭考勤后已经解绑的旧档案，也通过原编号历史复用。
