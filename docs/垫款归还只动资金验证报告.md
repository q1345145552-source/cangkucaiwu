# 垫款归还只动资金验证报告

验证日期：2026-10-18。全部写入验证在独立测试数据库完成，没有操作生产账目，没有部署。

本轮实现归还、部分归还、撤销、归还记录和凭证查看。按用户补充要求，垫款单增加币种，只允许使用同币种账户归还。没有新增运营支出或其他成本记录。

## 币种

- 新建垫款可选泰铢 `THB` 或人民币 `CNY`。归还账户下拉仅显示同币种的有效账户，后端也独立校验。
- 人民币测试：账户 20,000 CNY，归还 3,000 CNY 后为 17,000 CNY；泰铢账户仍为 10,000 THB。
- 人民币垫款使用泰铢账户被拒，资金、归还记录、垫款已还金额均不改变。
- 同一人同时欠款 3,000 THB、3,000 CNY，汇总人数为 1，两种币种分别列示，不合成“6,000 元”。接口新增 `totals_by_currency`；原金额合计字段在多币种时返回 `null`，单币种仍返回数值。
- 老垫款原先没有币种，新列默认 `THB`，原金额不转换、不改写。

## 数据库与资金口径

启动脚本增加两个迁移：

1. `cash_advances.currency`：`ADD COLUMN IF NOT EXISTS`，默认 `THB`。
2. `cash_advance_repayments`：`CREATE TABLE IF NOT EXISTS` 和幂等索引，各语句使用保存点。

归还表 20 个字段：`id`、`cash_advance_id`、`warehouse_id`、`repayment_date`、`amount`、`account_id`、`account_name`、`currency`、`payment_method`、`voucher_path`、`description`、`request_key`、`created_by_id`、`created_by_name`、`created_at`、`status`、`revoked_by_id`、`revoked_by_name`、`revoked_at`、`revoke_reason`。

原账户表只有月初余额 `opening_balance`，没有独立的实时余额字段。本轮保留月初余额原值，新增读取字段 `current_balance`，口径为：

```text
当前余额 = 原账户月初余额 - 此账户全部有效垫款归还金额
```

归还记录是这一笔资金流水的唯一来源，不再另写一条成本记录。撤销将归还状态改为 `revoked`，从有效扣减中剔除，余额随即恢复。收款账户列表和驾驶舱的账户余额使用同一读取函数。原有其他业务的账户记账方式未重构，此字段没有新增对其他业务收付的推算。

归还与撤销均锁定垫款单和账户，在同一数据库事务内更新归还记录、已还金额、状态及修改日志。模拟修改日志失败，已验证整笔事务回滚。前端使用请求编号防止网络重试重复扣款。有关联归还历史的账户禁止删除，可停用；有有效归还的账户禁止改币种，避免资金和历史记录失配。

## 接口与拦截

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| `GET /cash-advances/repayment-accounts` | 读取本仓有效归还账户及余额 | 仅仓库管理员 |
| `POST /cash-advances/repayment-voucher` | 上传归还凭证照片 | 仅仓库管理员 |
| `POST /cash-advances/{advance_id}/repayments` | 归还 | 仅仓库管理员 |
| `GET /cash-advances/{advance_id}/repayments` | 归还历史 | 原垫款单查询权限 |
| `POST /cash-advances/repayments/{repayment_id}/revoke` | 撤销归还 | 仅仓库管理员 |

上述路径统一带 `/api/v1` 前缀。主管、财务、劳工及超管调用归还、撤销、账户选择、凭证上传接口均为 HTTP 403“只有仓库管理员可以归还垫款”。跨仓垫款、归还记录、账户均被拦。

其他实际拦截：超额归还“不能超过剩余未还”；未选账户“请选择归还账户”；未传凭证“请上传归还凭证照片”；凭证必须真实存在且属于本仓；待确认或已驳回“待确认或已驳回的垫款单不能归还”；已还清“该垫款单已还清”；撤销未填原因“请填写撤销原因”。失败后资金和记录均不产生部分写入。
