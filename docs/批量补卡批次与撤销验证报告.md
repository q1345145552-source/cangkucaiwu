# 批量补卡批次、历史与整批撤销验证报告

日期：2026-10-18。验证使用本机隔离数据库和测试账号；未部署，未修改线上考勤或工资。

## 改动与接口

- 新表 `clock_in_makeup_batches`：仓库、补卡日期、操作账号/姓名快照、操作时间、原因、实际新建条数、状态、撤销账号/姓名快照、撤销时间。
- `clock_in_records.makeup_batch_id`：可空外键。旧打卡、旧补卡和原单条补卡保持空；不回填历史批次。
- 原 `POST /api/v1/clock-in/batch-makeup`：原验证、选人、时点、配置、跳过及额度规则不变，只在同一事务创建批次、关联本次新记录、写入实际条数，响应增加 `batch_id`。
- 新 `GET /api/v1/clock-in/makeup-batches`：仅仓库管理员可查当前仓库，按补卡日期的 `start_date/end_date` 筛选，支持分页，返回操作者、原因、条数、状态和 `can_revoke`。响应禁止缓存。
- 新 `POST /api/v1/clock-in/makeup-batches/{batch_id}/revoke`：仅仓库管理员，锁定当前仓批次后删除该批次当前仓的记录，批次留在表中，改为 `revoked` 并保存撤销人/时间；事务失败全部回滚。
- 状态为 `active` / `revoked`，前端显示“有效”/“已撤销”。新建条数不因撤销而归零，始终表示这批当初实际创建的条数。全跳过请求也留一个新建0条的批次。
- 非仓库管理员查询或撤销返回403：`{"detail":"只能由仓库管理员查看或撤销补卡批次"}`。其他仓库的批次和不存在批次统一404，不泄露批次内容。

## 启动迁移

`backend/scripts/seed.py` 新增 `_migrate_makeup_batches` 并接入启动流程。四条语句各用独立保存点：

1. `CREATE TABLE IF NOT EXISTS clock_in_makeup_batches (...)`。
2. `ALTER TABLE clock_in_records ADD COLUMN IF NOT EXISTS makeup_batch_id INTEGER REFERENCES clock_in_makeup_batches(id)`。
3. `CREATE INDEX IF NOT EXISTS ix_clock_in_records_makeup_batch_id ...`。
4. `CREATE INDEX IF NOT EXISTS ix_clock_in_makeup_batches_warehouse_date ...`。

失败会打印具体迁移项并抛错，避免缺表/缺列仍继续启动。迁移可重复执行，不重置已撤销批次，不更改旧记录的补卡额度字段，不修改工资单。

嵌入式 PostgreSQL 实际执行5组：正常、模拟建表失败、加列失败、两个索引各自失败；验证保存点保留之前的迁移、重试成功、重复运行不改数据。旧普通补卡和第一轮不占额度的旧批量补卡均保持原值，批次号都为空。

## 第二步：整批撤销的实际返回与考勤

手机点击批次1撤销，先显示“确认撤销这一批吗？会影响这一天这些人的考勤。已算工资单不会自动重算。”点击“暂不撤销”不发请求；再次打开并确认才撤销。

实际响应节选：

```json
{
  "message":"批次已撤销，已算工资单请按需人工重算",
  "batch_id":1,
  "deleted_count":8,
  "batch":{"id":1,"created_count":8,"status":"revoked","status_label":"已撤销","can_revoke":false,"revoked_by":1}
}
```

| 对象 | 撤销前 | 撤销后 |
|---|---|---|
| 员工1 | 4/4，正常出勤，8小时 | 0条，当天未打卡，0小时 |
| 选中员工B | 4/4，正常出勤，8小时 | 0条，当天未打卡，0小时 |
| 批次1 | 有效，新建8条，可撤销 | 已撤销，仍记新建8条，不再显示撤销按钮 |
| 旧普通补卡2026-10-16 | 1条，批次号空，计额度 | 原样保留 |

浏览器撤销成功提示“删除8条补卡记录”，历史和背后考勤即时刷新。数据库确认当天记录0条、批次1为revoked，撤销人1、撤销时间非空；旧普通补卡仍在，批次号仍为空。

重复撤销：400，`{"detail":"该批次已撤销"}`。

## 权限、隔离与事务

- 主管、财务、劳工、超管均不能查询或撤销批次，即使授予考勤权限仍403；管理员可以操作。
- 两个仓库各建批次，互相不可见、不可撤销；伪造未授权仓库请求头不能越仓。授权多仓的管理员选定仓库后，也只能查/撤该当前仓库的批次。
- 日期筛选、空结果、分页条数/总数、非法日期、倒置范围均验证通过。
- 撤销混合跳过的批次只删除本批新记录，保留另一批和原有正常/迟到记录；最终旧记录全字段快照一致。
- 模拟新记录插入失败：批次和补卡都回滚，无孤立批次。模拟撤销状态写入失败：已删除记录恢复、批次仍有效，操作原子性通过。
