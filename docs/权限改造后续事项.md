# 权限改造后续事项

以下规则由用户在第十二轮前明确决定，不再作为待确认问题：

- 配置中心：有“配置中心”权限的主管、财务都能读；写操作只给管理员和主管，财务不能改作息、红线。具体放开另行实施，第十二轮不改配置接口。
- 修改日志：按“修改日志”功能权限控制，勾了可看、未勾不可看。清单已有同名可勾项；旧接口的管理员角色限制需在后续对应轮次放开。
- 员工人数上限接口的既有 422 路由问题：排在这批改造后，单独一轮修复。

第十二轮只建立账号身份字段：

- `users.attendance_enabled`：默认 false，仅主管、财务的身份开关生效。
- `users.attendance_employee_id`：可空，关联员工档案；由服务端维护。
- `users.attendance_enabled_at`：可空，记录本次开启时间；关闭时清空。
- 第十二轮仅添加字段；第十三轮已实现打开时自动建档/复用并绑定，关闭只解除关联，不删除员工档案或业务记录。
- 权限清单中的 `attendance_enabled` / “纳入考勤”不可勾选、没有页面地址，不进入功能权限列表或菜单。

后续主管员工化须同步检查：打卡、我的考勤、加班确认/异议、我的工资单原先的劳工角色限制。本轮未改这些业务接口。

第十三轮绑定规则：

- 新档案姓名取账号显示名、工号沿用账号用户名、岗位为仓库主管、状态正式、仓库取账号所属仓库、入职日期取泰国当天。
- 薪资模板和扣款模板先留空，接口返回到员工档案设置模板的提示。
- 优先复用账号关联或已绑定该账号的档案；关闭后的原档案从该账号开关日志恢复关联，不按姓名猜测。
- 已绑定其他账号、跨仓库或已删除的档案不自动接管或恢复；返回中文提示。
- 建档/绑定、开关和修改日志在同一事务中完成；不改变账号角色，不修改工资、考勤计算或前端。
