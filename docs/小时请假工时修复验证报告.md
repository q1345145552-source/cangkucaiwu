# 小时请假工时修复

本轮只改小时请假的净工时及相应出勤折算。未修改生产数据、前端源码、工资发放/作废/重算动作、菜单、权限或数据库结构；未部署。

本地没有生产业务库连接。以下姓名为隔离样例，打卡严格复现用户提供的时间；样例时薪不能当作该员工线上实际时薪。

## 精确案例：Khin Than Dar Tway，2026-10-04

打卡：08:41:54、12:02:00、12:48:04、15:25:47。

测试配置：09:00–12:00、13:00–18:00，应有工时 8 小时。

- 打卡工时：3:20:06 + 2:37:43 = 5.963611… 小时。
- 早退：18:00 − 15:25:47 = 2.570278… 小时。
- 已批准小时假：2.3 小时，数据库记录不改。
- 额外应减：max(2.3 − 2.570278…, 0) = 0。

| 项目 | 改前旧公式 | 改后实测 |
| --- | --- | --- |
| 考勤净工时 | 3.66 | 5.96 |
| 新算工资逐日工时 | 3.66 | 5.96 |
| 考勤状态 | 请假2.3小时 | 请假2.3小时 |
| 小时假当天出勤占比 | 按原分档扣假 | 5.96 ÷ 8 = 0.745 |

真实浏览器屏幕：考勤显示“请假2.3小时 / 工时5.96h”；工资逐日弹窗显示“4号 5.96小时 (8:41 12:02 12:48 15:25)”。两个数字一致。

测试日薪 400，折算时薪 50：5.96 × 50 = 298，与新工资单“上班工资 298”一致。原有早退扣款 50 未改，样例实发 248；不能把应计工资 298 误报为实发。

日薪、月薪、按时模板分别验证，精确案例均为净工时 5.96、应计工资 298。月薪测试值为 12400，十月 31 天；小时假路径按净出勤比例折算当日未出勤部分，避免月薪再按原请假小时扣一次。其他假种仍走原有月薪扣款逻辑。

出勤在计算中使用净工时/应有工时，逐日明细保留 4 位；累计字段和原列表仍沿用两位展示精度，案例显示 0.74，不用这个显示值倒算工资。

## 共同实现与边界

`app/services/hourly_leave.py` 提供两边共用的小时假识别、打卡配对与净工时计算。

- 早退按配置中心 afternoon_end 计算，不写死实际下班点。
- 额外应减 = max(小时假合计 − 早退, 0)；净工时 = max(打卡工时 − 额外应减, 0)，最后保留两位。
- 一天多条先相加；累计达到应有工时或小时数为空，净工时为 0。
- 无时区时间、泰国时区及等价 UTC 时间得到相同结果。

| 场景 | 实测净工时 |
| --- | --- |
| 正常四次卡到18:00，打卡8小时，中途请假2小时没打卡 | 6 |
| 早退3小时，打卡5小时，请假2小时 | 5，不再额外减 |
| 早退1小时，打卡7小时，请假2小时 | 6，只额外减1小时 |
| 到19:00，打卡9小时，请假2小时 | 7，早退按0 |
| 精确案例，1.1+1.2两条小时假 | 5.96 |
| 精确案例，把配置下班改16:00 | 4.23，考勤工资一致 |
| 小时假8或9小时 | 0 |
| 小时假数值为空 | 0 |
| 没有打卡 | 0 |

## 不自动改老工资和请假记录

读取新考勤后，四张既有工资单的全部数据库列快照不变，包括人为保存的旧逐日3.66。已存工资仍保留旧结果，必须人工点重算后才采用新算法。本轮没有重算线上任何工资单，也没有改动原请假数据。

## 其他假种的既有偏差

按“全天/上午/下午算法一行不动”的范围，原全天、半天及无请假路径保持一致。

需要明确：原代码对于“全天假但仍有打卡”会在后端保留打卡工时；已有旧回归也明确期待该结果，并非0。无打卡全天假仍为0。这与用户验证项“全天假工时零”在带打卡场景存在既有差异，本轮没有扩大修改范围去修它。不能把这项描述为已修复。
