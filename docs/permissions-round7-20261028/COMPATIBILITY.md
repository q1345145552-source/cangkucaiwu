# 兼容、迁移和安全回退

本轮没有SQL结构迁移，没有修改模型；延用第六轮`extra_permissions`版本化三档授权及显式转换。最小选择器是附加查询合同，旧选择器保留但同样执行职责上限。

`migration-extended-01`使用独立合成库验证空/null/未知、混合版本、禁用、多仓、撤权重启、显式转换、并发撤权及审计失败事务回滚；`tiers-acceptance-01`和selectors证据区分八种三档组合。原始请求、前后数据、历史审计在相应目录，不修改真实库、不自动重新批准旧资金单。

历史待处理单缺少核验/批准证据仍安全拒绝；历史已完成记录不能重新执行。旧计划缺少准备证据时409，需真实核验/批准后重新准备有效计划；混币种执行整批拒绝。保留采购专用职责设置、版本和例外保护，不用通用设置覆盖。

回退须保留版本化权限数据与现有资金历史。不能直接降回旧全菜单授权或旧审批即出款实现；本轮无可提供的生产回滚执行记录。局部撤回最小表单UI必须同时保留后端职责/仓库/对象守卫，不能因界面兼容放松授权。任何实际生产升级或回退由用户另行授权，本轮未执行。
