## 测试调整原则

旧“主管直接付/本人批准/创建即出款”的成功期望不是必须保留的业务行为。金额回归使用合成独立录入人、核验人、管理员批准人和执行人，调用真实路由/JWT及数据库；不写伪造批准证据，不让鉴权永远放行。

原7000工资、1000预支、2000报销、9000归还、30/40部分批准、300+700应付、400+600跨月应付、0.1+0.2精度及其他有效金额断言保留。旧角色和无敏感字段拒绝文案改成真实职责断言；目录集合增加既已注册的新路由，不以模糊包含放过未登记接口。

成本冲突使用`DeferredChecks`只延后明确独立的只读比较，最终`finish()`汇总抛出断言并非零退出；不包裹失败的创建或执行，不skip/xfail，不吞掉金额失败。历史撤销底层夹具的鉴权覆盖与真实停用入口验收分开，覆盖统计排除带任何鉴权覆盖的请求。

## 已确认职责

主管负责现场和本人自助，不管资金账户、正式财务记账、核薪发薪、资金批准、财务规则，不自批。财务核验并在有效独立批准后执行，本人/受益人不能自批自付。管理员在授权仓库批准和设置规则。工资交接为现场事实→财务核算→管理员确认→独立财务发放。上述不是待确认政策。

真实待决的是历史成本含义、外部评估不可达入口是否恢复等新增政策；本轮没有代替用户决定。
