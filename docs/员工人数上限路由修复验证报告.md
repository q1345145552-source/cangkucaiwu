# 员工人数上限路由修复

基线 ba9cc23。本轮只修员工人数上限，不处理配置中心和修改日志后续事项，不部署。

## 改动范围

将 `backend/app/api/v1/employees.py` 中的 GET、PUT `/max-limit` 两个完整函数前移到第一条员工路由之前，确保先于 PUT `/{employee_id}` 注册。原路径、查询参数、权限校验、仓库处理、函数内容完全保留。

新增测试将基线和当前文件逐函数比较 AST，并比较移走两个函数后的剩余代码：内容完全一致，只有两个路由的注册位置变化。前端、数据库模型、迁移和其他业务模块均无改动。原第三、十轮测试里期望旧故障422的断言改为修复后的200；劳工仍403。

## 实际验证

使用本地隔离数据库和未修改的原前端构建，管理员登录原员工页面，将人数上限从50改为73，成功提示“人数上限已设为 73”。刷新页面，再打开设置，输入框回显73，页面显示“1 / 73 人”。

原接口返回：

```json
PUT /api/v1/employees/max-limit?max_employees=73
HTTP 200
{"message":"人数上限已设为 73","max_employees":73}

GET /api/v1/employees/max-limit
HTTP 200
{"max_employees":73,"current_count":1}
```

独立数据库会话确认仓库1的 max_employees=73，仓库2不变。工资记录逐字段快照不变。无权限主管、财务仍403；授予员工档案权限后正常读写；劳工403，伪造外仓请求头不能修改外仓。

员工新建、编辑、列表回显、员工资料汇总 `/employees/{id}/summary`、离职、删除成功；不存在的员工编辑仍404。项目没有独立的 GET `/employees/{id}` 详情路由，界面详情沿用列表数据和资料汇总，没有新增接口。
