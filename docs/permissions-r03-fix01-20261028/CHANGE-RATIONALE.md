# 第三轮 fix01：断言与夹具变更理由

本补修没有业务代码修改。范围为协调指定的14个受影响回归文件及其必要夹具、采集器。原277目标组不能替代旧业务断言；本报告以当前真实请求和逐行执行记录为准。

## 真实前置与资金阶段

- `round3_flow_support.py` 调用实际JWT/应用路由。主管4申请、财务3核验、管理员1批准、财务3独立执行；没有生成批准摘要、替换鉴权、改角色或设置永远放行的依赖。
- 合成身份仅补对应菜单权限；角色上限仍由真实后端执行。工资合成草稿先通过管理员真实confirm，不能只把数据库status写成confirmed当批准。`prepare_payroll`只把未支付的合成种子设置为草稿，再调用confirm；已支付/作废种子直接断言失败。
- `money_state`比较费用、应付付款、报销付款、垫款归还、备用金项及备用金余额。核验和批准前后必须相同。预支执行后才检查原1000金额、三来源余额/额度/账本效果。执行故障回滚时，已存在的申请及有效批准仍保留，因此旧“创建失败应无申请”改为“申请1条且无付款关联”，不删除资金回滚断言。
- 新建主管代他人预支、管理员登记垫款也仅pending。审批输出approved_ready而非已出款；工资仅在实际出款后扣除预支债务，保留1200−1000=200、800−100=700及重复重算/跨期结转断言。
- `test_employee_advance_void.create`返回真实创建与执行响应字段的合并字典，保留limit_check用于原额度断言；不是伪造HTTP响应。

## 历史撤销与失败回滚

删除受影响文件中的`retained_reversal_code`使用，保留所有HTTP停用守卫。`assert_disabled`还检查拒绝依赖不在dependency_overrides内。

历史合成夹具使用直接SQL建立已撤销结果，包括原付款金额、归还金额、关联账务标记；不调用撤销HTTP成功路径，不直接调用旧撤销处理器，也不伪造新批准。读取使用真实接口验证2000报销、1000归还、工资未付及已冲销账本；拒绝重复撤销后全表/全字段快照一致。历史审计明确标记synthetic historical，不称线上真实审计证据。

旧“撤销时注入错误应回滚”在关闭入口已不可达，改为在同样已支付数据和故障注入条件下验证停用拒绝、全部业务记录不变。真正支付/归还故障注入仍实际触发500，并检查整笔/整批回滚。垫款工资没有费用创建分支，因此其第二笔失败注入移到实际`cash_advances/payroll_use`日志处；两条工资的使用额度和所有相关记录回滚为0，未改业务实现。

## 合成资金余额及源码检查

旧夹具账户期初10000并同时插入500+250已付费用，真实可用9250，旧断言却期待10000。本补修将仅合成夹具期初改10750，使初始可用严格10000；原付款后7000/8000/3000、币种独立及不开销重复扣减等断言保留。独立基线也使用相同合成修正，差异文件留存。工资费用夹具账户补足合成余额，才能实际支付1234.56；未修改真实期初、库存期初或余额公式。

全模块源码字节恒等不能用于允许新增守卫的模块：改为检查实际`_compute_employee_records`、`_rollback_advance_deductions`或对应金额服务；相应服务与第二轮基线的比较结果见validation.json。没有把源码字符串当路由验收，真实金额断言、HTTP/数据库测试均实际运行。

## 保留失败而继续后续检查

`DeferredChecks`只捕获显式独立读取断言的AssertionError，`finish()`最终必定重新使该测试失败；没有skip/xfail、忽略退出码或把失败转为通过。它用于保留已知成本差异的红色断言，同时让余额、账本、额度、重复请求、历史读取等后续断言执行。设置/请求/鉴权等前置不在捕获范围内。

8个测试仍失败。3条垫款工资“生成的费用行字段/联动费用删除保护”断言由于不存在费用记录不能执行；旧断言保留，先行“必须生成费用”失败记录保留，本报告不声称这3条通过。其余参数分支的未到达行以同一函数其他参数的真实跟踪映射，不用测试名推断通过。

## 逐断言审查方法

`assertion-map.json`保留124项旧首错完整堆栈、原失败调用行、729条原断言文本、当前表达式/测试ID/文件行、实际到达/失败状态。AST完全相同表达式直接对应；历史字典响应及分拆断言有显式映射。非完全相同表达式均明确标为changed，不能仅凭文本相似度认定等价；本页给出实际职责/状态变化理由，`fix01_assertion_overrides.py`保存人工核对的特殊映射。

“执行到断言所在行”不保证短路表达式中每个操作数都执行；失败行、未执行分支、整项失败状态同时保留。695条对应场景到达、31条在对应参数分支到达、3条缺费用对象未验证，不能写成729条全部通过。
