# 兼容与回退

没有模型、数据库结构或数据迁移；没有在真实数据库执行任何操作。第一至三轮的证据目录保持原样。

正式员工绑定是自助身份来源。旧版按姓名/电话推测身份不再授权；未绑定、离职、禁用、冲突绑定安全拒绝，须由已有合法管理员维护真实绑定。本轮不自动绑定、开通考勤或补数据。财务已有正式绑定时仍可看本人工资条；打卡/考勤需要既有考勤开通及匹配绑定。主管保留既有更严考勤绑定条件。

本人资金申请显式view=self，不获得管理菜单。预支来源由申请人明确选择；返回公司账户仅ID、名称、币种，不返回余额或完整账号。资金申请后仍走第二/三轮核验、批准和独立执行，未自动批准、未执行历史资金记录。

新增补卡申请用既有data_change_history表的module=makeup_request保存业务请求，after_data保存pending/approved状态与事实；它不是可随意清理的普通日志。独立人员批准后才调用原补卡服务并同事务更新状态，不改变补卡额度和工时计算。历史其他module不作申请，不自动补卡。当前没有新增撤回、驳回补卡申请接口；如需补齐请求生命周期应另行明确范围。回退到旧代码前须保留这些记录，未批准申请停止处理，不能把它们自动视为批准；已生成考勤继续保留。旧版本不识别该module但不应删除记录。没有数据库降级脚本。

规则/员工审计新增operation_type=r04_change，记录对象、操作者、仓库、字段名及摘要。薪资/扣款规则保留必要规则值；个人银行等字段只留摘要，不增加明文敏感字段。拒绝请求允许安全日志，但业务状态不得变化；makeup_request被作为业务状态单独比较。

如回退本轮源代码会重新开放本轮修复的权限旁路，不能以“无需数据库迁移”推断安全可回退。应先独立验收，按受控代码回退流程决定；本轮未执行回退或部署。
