## 发现与修复

1. **到账预览持有账户写锁。** 原实现调用`lock_account`，按文件顺序持有`FOR UPDATE`到请求结束。相反顺序预览/其他多账户操作存在等待甚至死锁风险。新增SQL跟踪用例在f390302上复现预览持锁。改为同一个账户条件校验实现提供只读查询；原`lock_account`默认行为及账户归属、状态、币种校验全部保留。确认保存时先按账户编号排序加锁，再调用原批量登记/逐笔幂等服务。验证真实账户写锁被另一个事务持有时，预览仍可完成；预览没有业务表DML。现有POST审计中间件的`audit_logs`写入保留，不为通过测试关闭审计。

2. **预览版本未绑定操作账号，到账版本还未绑定原始文件内容。** f390302上，账号A的未提交预览可直接由同仓有权限账号B确认；当时的确认签名虽绑定确认账号，却无法证明此账号做过对应预览。物流与到账现在都把预览账号纳入版本；到账同时加入原文件SHA-256，防止用“解析值相同、文件内容不同”的文件替换已核对文件。原有仓库、物流供应商、文件字段校验继续生效。跨账号、跨仓旧预览被拒绝；当前账号/仓库重新预览后可合法保存，没有改变权限政策。已成功保存的旧请求仍先按原签名返回原结果，不受新预览算法或源对象停用影响。

3. **文件/入口替换仍可能沿用旧确认，旧异步失败可能覆盖新入口状态。** f390302前端用例复现：新文件尚在预览时，旧确认按钮仍可用。现在把预览绑定到实际File对象、入口及资源；变化后清空预览、待确认状态和勾选，提交按钮立即检查绑定。用请求代次隔离迟到的成功/失败结果，切仓/切账号后不展示旧错误或把旧请求挂到新范围。新文件的确认必须重新勾选。旧范围中结果不明的草稿继续保留，回到原范围可用原文件、原编号恢复。

4. **结果不明、实际未提交、预览随后变化时可能永久冻结。** 原客户端对待确认请求保持冻结，即使服务端409说明预览已变，也无法安全重新核对。现在只有在仓库锁内确认该导入操作记录不存在、且尚未执行本批写入时，才返回带精确请求编号的`excel_import_not_saved/not_created`凭据与当前预览。客户端校验凭据所属请求，解除“结果不明”，重新要求人工核对；仍保留原请求编号。普通错误、错误编号、已保存请求内容冲突均不能解除冻结。沿用原编号确保竞争中的旧请求即使先保存，也只会使新内容冲突，不会新增第二批。

## 复核确认原有保护成立

- 物流和到账确认均持仓库锁，再查询持久化导入请求；同一原请求的6个并发重试仅一批新增，其余返回原结果。
- 使用数据库`after_cursor_execute`在真实INSERT执行后注入异常，业务记录与导入请求记录均回滚为0；移除故障后原编号可重试成功。不是只检查解析/校验失败。
- 丢弃成功响应后按原编号重试；供应商或账户随后停用，仍返回已保存的原结果，不重复新增。
- 已保存请求换账号返回冲突；换仓库不能使用旧预览或读取旧范围请求。每个仓库重新预览的独立请求可以合法保存，回原仓重试仍是原批。
- 原有同日期同金额的独立到账仍可合法登记；没有按金额/日期删除、合并或拒绝合法业务。
