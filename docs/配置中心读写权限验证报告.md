# 配置中心读写权限修补

基线 e970f41。本轮只处理配置中心及其共用读取依赖，修改日志未动，没有部署或操作线上数据。

## 接口清单

页面调用4组共8个接口，路径均带 `/api/v1` 前缀：

| 路径 | GET读取 | PUT写入 |
|---|---|---|
| `/config/work-schedule` | 仓库管理员；有配置中心权限的主管、财务。返回8个时点、月度加班上限和editable | 仓库管理员或有配置中心权限的主管 |
| `/expense-approvals/threshold` | 保留配置中心或费用审批任一权限读取，原角色规则不变 | 仓库管理员或有配置中心权限的主管 |
| `/suppliers/purchase-approval-threshold` | 保留供应商共用读取；有配置中心权限的财务新增可读。财务仅有供应商权限时仍保持原403 | 仓库管理员或有配置中心权限的主管 |
| `/suppliers/concentration-threshold` | 保留采购分析或配置中心任一权限读取，原角色规则不变 | 仓库管理员或有配置中心权限的主管；仅采购分析权限不能写 |

四个PUT均保留菜单权限依赖，统一通过配置写入角色检查。有配置中心权限的财务返回HTTP403、`财务只能查看配置中心`。无权限主管/财务由原权限依赖返回“无此操作权限，需要: …”。劳工拒绝。

超管处理照旧：完整作息、费用门槛、采购门槛及写入均保留原拒绝处理；集中度阈值共用GET保留原行为，没有扩大超管业务访问范围。

editable由后端计算：仓库管理员true，已通过配置权限校验的主管true，财务false。前端12个输入框在只读时禁用并呈灰色，两个保存按钮隐藏，提示说明仓库管理员和已授权主管可修改。表单内容、参数及保存逻辑未改。

## 考勤共用读取的兼容处理

发现 `ClockRecordsGrid` 和考勤页面原来同样调用完整 `/config/work-schedule`。如果只收紧原接口，未勾配置权限的主管在考勤页面将无法取到实际作息，可能回退默认时点。

因此增加只读 `GET /config/attendance-times`，保留这两个旧调用的仓库管理员/主管访问范围，只返回 morning_start、noon_break_start、noon_break_end、afternoon_end四个打卡时点，不含红线、上限、审批门槛或editable。超级管理员、财务、劳工保持该旧共用调用的拒绝规则；员工自助打卡仍使用自己的原接口。

两个前端使用点各只替换一处URL，其他代码逐字与基线相同，测试已验证。没有修改考勤或打卡业务接口、数据计算、工资服务。配置服务 `get_work_schedule` 及各模块内部读取方式未改。该兼容入口不能用于绕过完整配置权限。

## 第一步：财务读取及界面

本机隔离测试管理员为财务staff授予配置中心。真实登录后菜单有配置中心，页面可见：

- 作息09:00、12:00、13:00、18:00。
- 迟到红线09:05、09:31，早退红线17:00、17:30。
- 月度加班上限50。
- 费用审批门槛42泰铢、采购审批门槛123泰铢、集中度预警阈值80%。

12个输入框均禁用；“保存作息”“保存审批门槛”均不显示，因此财务不能在页面发起保存。截图 `/tmp/config-finance-readonly.png`。

完整作息GET实际HTTP200返回：

```json
{"morning_start":"09:00","late_half":"09:05","late_one":"09:31","noon_break_start":"12:00","noon_break_end":"13:00","early_one":"17:00","early_half":"17:30","afternoon_end":"18:00","overtime_limit":50.0,"editable":false,"warehouse_id":1}
```

## 第二步：财务直接写被拒

用有配置权限的财务分别调用四个有效PUT请求，均为HTTP403：

```json
{"detail":"财务只能查看配置中心"}
```

未通过前端隐藏来代替后端校验。

## 第三步：取消财务权限

只在隔离库撤销测试财务权限，重新登录，菜单只剩仪表盘，没有配置中心。另用实际登录令牌直接读取完整配置，HTTP403：

```json
{"detail":"无此操作权限，需要: 配置中心"}
```

其他业务页的共用阈值读取仍可使用其原有业务权限，这不代表有完整配置页面访问权。

## 第四步：主管保存及恢复

主管supervisor授予配置中心后真实登录，editable=true，12个输入框可编辑，两个保存按钮均可用。浏览器将月度加班上限50改为65，保存提示“作息设置已保存”，刷新后仍65，再恢复50并保存成功。点击审批门槛保存也提示“审批门槛已保存”，原42、123、80值未改。截图 `/tmp/config-supervisor-saved.png`。

独立HTTP测试进一步将上班点和迟到红线改为08:30、08:35、08:50、月度上限65，HTTP200返回：

```json
{"message":"作息设置已保存","morning_start":"08:30","late_half":"08:35","late_one":"08:50","noon_break_start":"12:00","noon_break_end":"13:00","early_one":"17:00","early_half":"17:30","afternoon_end":"18:00","overtime_limit":65.0}
```

回读editable=true且数值一致；随后恢复为09:00、09:05、09:31和上限50，HTTP200。三个阈值PUT也分别验证保存80并可回读。
