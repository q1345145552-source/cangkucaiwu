# 第三轮状态、证据与兼容

无模型、列、数据库结构迁移；没有在真实数据库执行任何操作。现有字符串状态列和DataChangeHistory事务历史保存批准证据。证据记录操作者、对象、仓库、动作与内容SHA256，不复制薪资/证件/银行敏感字段。

|对象|新流程|历史处理|
|---|---|---|
|工资|核算pending → 管理员confirmed且保存快照 → 独立财务发放|历史confirmed无快照拒付；管理员可按既有未支付重算/作废入口重新生成待确认单；已支付禁止物理删除、重算或恢复撤销|
|普通报销|本人申请pending → 独立核验（状态不变，历史证据区分）→ 管理员approved/partially_approved/rejected → 独立付款|旧批准没有证据不能付款；未付款普通单可由管理员return-to-draft，明确重新核验审批；旧已付款不重付|
|员工预支|pending → verified → approved_ready → approved（已执行出款）|旧approved不自动补审批、不重复执行；缺资金事实的旧approved须独立核对，本轮不擅自改回待处理。未出款的新状态计入既有额度占用，但工资仅抵扣已执行approved，额度公式不变|
|垫款|pending，核验后仍pending但展示待批准 → 管理员confirmed且快照 → 独立财务还款，全部还清repaid|旧confirmed无证据不能还款或作为新付款来源；未使用记录可按原管理员编辑权限退pending重新核验。已使用历史缺证据记录只拒绝，需独立核对处理方案；不补历史批准|
|应付|采购/匹配事实保持；另行财务核验 → 管理员资金批准 → 独立财务部分/全部付款|采购通过不等同资金批准；历史未付/部分付款可在原账单上真实核验批准，只能支付剩余；已付/作废不能新付款|
|付款计划|财务准备计划且保存内容证据 → 验证每张应付管理员批准 → 原子执行|旧计划没有准备证据拒绝；可按当前合法剩余账单重新生成计划，旧计划不补证据或自动执行|

批准绑定金额、币种、父子单/受益人、相关原始凭证；工资还绑定员工、结算期间、计算函数版本、相关模板及源考勤/扣款/预支/规则。非实质付款进度字段（已付累计、执行时间、首次付款生成的成本关联编号等）排除，防止正常部分付款误使剩余额度批准失效。原付款金额上限、采购匹配、账户有效性/币种/余额检查仍独立执行。

工资来源快照目前对员工预支、仓库配置仍较保守，部分非本次计算的变化也可能要求重确认；不会自动放宽批准。跨进程同时修改源考勤与发薪的竞态未做压力测试，不宣称所有来源更新都已串行化。

本人判断同时检查申请/录入者、受益登录账号、员工正式绑定及考勤别名。手填垫款人姓名而无可验证账号允许登记，但不能核验批准付款；必须先按原编辑权限核对关联账号。不选择替代审批人，无独立批准人时拒绝。

第二轮备用金30/10部分批准仍只付30一次，保留原预留40；不自动释放驳回10、不改费用归属。第二轮完整核验/批准证据继续使用，其历史缺证据处理保持。

回退不是简单覆盖旧代码：旧代码会重新开放自动批准出款，并不能正确解释verified/approved_ready。安全回退应保持资金写入口关闭并人工核对状态与历史证据；本轮没有执行回退、生产升级或任何历史批量补数据。

员工预支的费用日期继续沿用原审批/申请日期口径；新增执行事实的实际时间和操作者另存事务历史。本轮不擅自重划费用期间。
